# 后端历史发现需求

## 1. 产品需求

1. 每种前端绑定都必须能够向 Agent 后端查询属于当前已配置工作区的历史会话。
2. 历史会话摘要必须包含规范会话 ID 及其第一条 `user_message` 的内容，必要时使用明确的有界/截断表示。
3. 前端绑定必须能够读取选定历史会话的规范事件以供展示，并能选择一个历史会话作为恢复目标。
4. 历史发现、JSONL 解析、校验、投影和恢复选择均属于 Agent 后端能力。传输适配器可以映射这些能力，但不得扫描文件、导入 `SessionStore`，也不得接受普通前端提供的文件系统路径。
5. 生产会话记录只有一个存储位置：`<workspace>/.coding-agent-neo/sessions/`。必须移除生产环境的 `session_dir` 配置字段和 CLI `--session-dir` 选项。
6. 恢复必须保持现有线性会话语义：复用 Agent 会话及根 Agent 身份、继续分配序列号、重建上下文和预算，并且绝不重放历史工具副作用。

## 2. 安全与生命周期需求

1. 前端不会获得工作区路径、会话目录路径、任意文件名或原始文件系统访问能力。
2. 历史查找和恢复只接受经过校验的不透明 `session_id`；目录组件、绝对路径、`.jsonl` 文件名、路径穿越和符号链接逃逸均被拒绝。
3. 只有固定会话目录直接拥有的常规 `.jsonl` 文件才是候选项。单个格式错误或不可读的候选项不得导致完整历史列表失败。
4. 历史事件读取和首条消息投影必须有界。无效文件只暴露稳定、安全的诊断，绝不暴露回溯、原始配置、凭据或无关文件内容。
5. 创建恢复会话时必须重新校验所选文件。先前的历史列表响应绝不构成授权，也不能证明该文件仍可恢复。
6. 现有单活跃传输会话规则继续生效。恢复请求不能替换活跃会话。

## 3. 必需交付物

1. 实现前更新 `docs/agent-backend-interface.md`，使其定义工作区范围的后端提供者、历史 DTO、有界读取、错误和恢复创建语义。
2. 实现前更新 `docs/agent-transport-interface.md`，使 In-process 和 HTTP/SSE 绑定暴露等价的历史与恢复能力。
3. 实现固定的生产会话位置，并移除公开的 `session_dir` 配置和 CLI `--session-dir` 支持。
4. 实现由后端拥有的历史发现、摘要投影、历史事件读取及会话创建/恢复。
5. 在本工作流中通过 In-process 和 HTTP 两种适配器映射该能力，但不修改 Web UI。
6. 针对变更边界补充相称的单元测试、传输一致性、集成、安全、架构、CLI 和配置证据。

## 4. 明确排除项

- 不提供任意工作区文件浏览器或原始 JSONL 下载端点。
- 不重新设计 Web UI，也不在 `web/` 中实现历史选择器。
- 不包含远程/公开部署、认证系统、多工作区控制平面、JSONL 迁移、删除、重命名、导出或按消息文本搜索。
- 除选择固定持久化路径所需的组装变更外，不改变 Agent Loop、模型、工具、策略或执行环境行为。
