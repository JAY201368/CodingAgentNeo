# 决策日志

只记录具有下游影响、持久且非显然的决策。

## 2026-09-01 — 启动工作流时将会话存储固定在各工作区之下

- 选择：生产会话记录只存在于 `<resolved workspace>/.coding-agent-neo/sessions/`；直接移除 `session_dir` 配置和 CLI `--session-dir`，而不是弃用它们或为其提供别名。
- 理由及被否决的替代方案：可单独配置的目录无法从本质上证明工作区归属，并会使跨工作区发现持续存在歧义。
- 后果：不会自动发现或迁移现有自定义会话目录；测试可以使用内部依赖注入，但普通前端不能选择目录或路径。

## 2026-09-01 — 启动工作流时采用一个工作区范围的后端提供者

- 选择：适配器接收一个 `AgentBackendProvider`，由它负责历史列表/读取以及新建/恢复后端；每个返回的 `AgentBackend` 仍负责一个实时线性会话。
- 理由及被否决的替代方案：把历史能力放到已经创建的会话句柄上会形成启动循环；让适配器在后端之外调用仓库则会形成被禁止的持久化旁路。
- 后果：后端和传输规范必须对提供者/DTO/错误契约进行版本化；组装和适配器发生变化，但 Agent Loop、工具、模型、策略和环境保持不变。

## 2026-09-01 — 启动工作流时决定返回投影而非原始 JSONL

- 选择：历史列表返回包含第一条规范根用户消息的有界摘要，历史查看返回规范 EventEnvelope 值的有界分页。
- 理由及被否决的替代方案：原始文件或调用方提供的路径会暴露文件系统/配置细节，并绕过规范校验。
- 后果：适配器映射有限 DTO 和稳定安全错误；实时事件仍使用基于游标的迭代器/SSE，Web UI 消费被延期。

## 2026-09-01 — T01 对单一提供者和有限历史绑定进行版本化

- 选择：两种适配器都接收一个工作区范围的 `AgentBackendProvider`；历史列表/读取返回不可变的 v1 DTO 分页，采用最新优先的列表顺序、基于序列的事件分页、4,096 字节首条消息投影和有界诊断。事件历史是有限 JSON；只有实时事件使用迭代器/SSE。
- 理由及被否决的替代方案：提供者把持久化和恢复授权置于一个后端依赖之后；明确的边界和不透明列表游标则防止无界响应或由路径派生的前端输入。
- 后果：T02–T05 需要实现固定的 `workspace/.coding-agent-neo/sessions` 位置、`session_...` ID 校验、`1..100` 列表限制和 `1..200` 事件限制、稳定的历史/恢复错误以及 HTTP `resume_session_id` 请求，同时不得恢复 `session_dir`/`--session-dir`；这些能力现已交付。T01 没有改变产品实现或 Web 测试夹具。

## 2026-09-01 — T02 从解析后的工作区派生持久化和恢复目标

- 选择：`AppConfig` 只携带解析后的工作区；组装层将每个生产会话文件派生为 `<workspace>/.coding-agent-neo/sessions/<session_id>.jsonl`，恢复只接受严格的不透明 `session_...` ID。
- 理由及被否决的替代方案：保留路径或 ID 解析器会留下由调用方控制的持久化边界，并允许恢复无关工作区中的记录。
- 后果：旧版 TOML、`CODING_AGENT_NEO_SESSION_DIR` 和 CLI `--session-dir` 输入会作为未知配置被拒绝；恢复提示只包含 ID；基于直接路径的恢复仅通过内部 `recover_session_plan(path)` 测试接缝保留，用于覆盖格式错误记录。现有自定义目录既不会被发现，也不会被迁移。

## 2026-09-01 — T03 将历史投影保持在单一提供者之后

- 选择：公开提供者端口拥有不可变有界 DTO 和稳定安全错误；由组装层拥有的固定目录仓库解析规范 JSONL 并保存短期不透明列表游标；必要时事件分页会降低载荷预览边界，使完整响应保持在 8 MiB 以内。
- 理由及被否决的替代方案：将仓库访问和恢复校验留在提供者内部，可以防止适配器打开路径或重建会话事实；在信封载荷处进行投影，则能在不返回原始 JSONL 的情况下保留规范 ID 和序列。
- 后果：列表将格式错误候选项隔离为有界诊断，直接读取/恢复会重新校验当前固定文件，不完整尾部仍可携带诊断恢复，T04/T05 将适配器绑定到提供者而不是仓库或后端工厂。

## 2026-09-01 — T04 使 In-process 工作区绑定由提供者支持

- 选择：`build_in_process_workspace_binding(config, interactive=...)` 返回会话创建前的 `InProcessWorkspaceBinding`；其列表/读取/创建方法只委托给一个工作区范围的 `AgentBackendProvider`，兼容构建器只创建一个由提供者拥有的会话。
- 理由及被否决的替代方案：在兼容构建器中直接构造后端会留下绕过历史契约的第二条组装路径；该绑定在保留基线 CLI 门面的同时，将历史选择和单会话生命周期置于同一提供者之后。
- 后果：受控 Python 调用方可以在创建会话前分页读取历史，恢复后的适配器保留 `resume_last_sequence`/`resume_diagnostics`，CLI 不透明 ID/错误行为保持兼容，而 HTTP 仍是独立的 T05 绑定。

## 2026-09-01 — T05 将 HTTP 组装保持为仅依赖提供者

- 选择：HTTP 注册表接收一个 `AgentBackendProvider`；只有在强制执行单活跃会话槽位后，才要求该提供者创建新后端或恢复后端，并根据提供者拥有的 `resume_last_sequence` 元数据初始化恢复后的传输游标。
- 理由及被否决的替代方案：将后端工厂传入注册表或在 HTTP 应用内部适配工厂，会保留一条无法暴露历史或恢复语义的第二组装路径。组装根构造工作区范围的提供者，并把这一项依赖传给 HTTP 应用。
- 后果：有限历史路由无需导入 `SessionStore`、仓库、路径或 In-process 适配器即可映射带类型的提供者错误；HTTP 调用方必须为实时会话和历史提供规范的提供者契约。

## 2026-09-01 — T06 在提供者边界关闭适配器工厂接缝

- 选择：规范集成路径使用一个工作区范围的 `AgentBackendProvider`，同时负责有界历史以及新建/恢复后端。`backend_factory.py` 和兼容构建器只为经过提供者路由的兼容调用方保留；它们不是 HTTP 或 In-process 适配器依赖。
- 理由及被否决的替代方案：T04/T05 之后继续保留旧的共享工厂实现索引，会描述第二条适配器组装路径，并与已验收的提供者契约矛盾。重新指向权威索引可在不删除经过测试的兼容门面的情况下，使实现、测试和传输文档保持一致。
- 后果：固定的 `<workspace>/.coding-agent-neo/sessions/` 位置仍是唯一生产存储，旧版自定义目录不会迁移，Web UI 消费仍被有意延期到本工作流之外。T06 的验收和提交由主代理负责。
