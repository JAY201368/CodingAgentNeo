# Web GUI 历史侧边栏 scripted 验收对照

本表把 T07 与 T08–T10 要求的 scripted Web 验收项映射到**仓库里真实存在的** Vitest 用例名。缺口才补测试，不另造第二套协议、Playwright 真模型旅程或虚构用例名。

Python 聚合验收 `tests/acceptance/test_webgui_history_sidebar_acceptance.py` 只做静态边界扫描（`v-html`、Python import、fetch/localStorage 所有权、git 生成物/secret、README 运行说明），不冒充真实浏览器或真实模型网关。

## T08–T10 纠偏旅程

T09 把部分 T07 App 用例改名（例如 `resumes the selected history session...` → `resumes a history item...`；标题行不再假设主区已有对话）。本表只引用改名后的真实用例。未补新的聚合 Vitest：八条纠偏旅程已有 App / composable / reducer 证据。

| 验收项 | 证据（文件 / 用例名） | 说明 |
| --- | --- | --- |
| 首屏零 session 副作用且右侧空白 | `web/src/App.spec.ts` — `loads history on first mount with zero session side effects and a blank main pane`、`does not attach a persisted transport hint on mount`、`places the title in the sidebar and keeps the main pane blank until the user acts` | 只发历史列表 GET；`POST /sessions`、attach、live SSE、DELETE 均为 0；即使有持久化 hint 也不自动 attach；右侧无「尚未连接」/控制卡 |
| 侧边栏新建 | `web/src/App.spec.ts` — `creates from the circular button, DELETEs a known transport first, and clears the current history item`、`creates a session from the sidebar, submits one task, and renders the ordered final timeline`；`web/src/components/HistorySidebar.spec.ts` — `renders a keyboard-reachable circular create button with aria-label`、`emits create from the circular button`；`web/src/composables/useAgentSession.spec.ts` — `deletes the known transport then POSTs an empty create body once`、`skips DELETE when there is no known transport and still POSTs once` | 圆形 `aria-label="新建 session"` 是唯一新建入口；有已知 transport 时先 DELETE 再 `POST {}` |
| 已有 transport 下历史 replacement | `web/src/App.spec.ts` — `DELETEs a persisted transport before resume replacement`；`web/src/composables/useAgentSession.spec.ts` — `cleans a persisted hint before resume without attaching it`、`deletes a persisted hint that has not been attached before creating`、`terminates, resets, resumes, hydrates in sequence, then attaches SSE from the reducer cursor` | replacement 先 DELETE 前端已知 transport（含未 attach 的持久化 hint），再唯一一次 resume/create POST |
| 旧 `session_end(INTERRUPTED)` 不毒化新 transport | `web/src/App.spec.ts` — `restores a history session that ended INTERRUPTED without a fake disconnect entry`；`web/src/composables/useAgentSession.spec.ts` — `keeps the new live transport connected after historical INTERRUPTED terminal events`；`web/src/domain/reducer.spec.ts` — `keeps live connection open when historical terminal events hydrate`、`still closes the live transport on a live EVENT session_end` | 历史 `HYDRATE_EVENT` 只重建 timeline；旧 `session_end`/`INTERRUPTED` 不关闭或遗忘新 live transport；composer 可 follow-up，无伪「连接已中断」入口 |

## 明确未声称的证据

- 真实模型网关、真实浏览器端到端 resume、公网/远程部署均未在本工作流执行。
- T06 / T10 人工 1280/360 布局与独立滚动检查是离线视觉证据，不替代本表的 resume 状态机证据，也不冒充真实模型。
- 既有 `tests/acceptance/test_web_frontend_acceptance.py` 覆盖 live HTTP/SSE 任务/工具/授权/follow-up，不覆盖历史侧边栏 UI；历史 list/events/resume 的 Python wire 证据在 `tests/integration/test_http_history.py` 与前序 `docs/backend-history-discover/`。
